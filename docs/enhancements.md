# Enhancements

The enhanced edition plays the original's own scripts, ported to C++. Each change from the original is
listed here with what the original did. Where a change affects play, it can usually be switched off; a few are build-time switches, and
some (such as the pause) have none.

This is the player's view. The full record, with the reasoning, the code and the measurements
behind each change, is the enhancements table and the steps of
[`planning/2026-09-27-penumbra-port.md`](planning/2026-09-27-penumbra-port.md).

| # | Enhancement | The original |
|---|---|---|
| E1 | Widescreen. The view is 768 logical pixels tall and as wide as the window. The menus, the options, the arena select and game over keep the original's 1024x768 layout, centred. In a wider window (a 16:10 or 16:9 monitor, a 20:9 or 21:9 phone, up to 4:1) their scene carries on past the sides instead of showing black bars: the floor and walls are continued with the scenes' own tiles, and a fade or the menu's panel against the edge reaches the window's edge. The pointer and a tap reach that area too. With widescreen off, everything is the original's 4:3 with bars, and over the bars the system pointer shows, since the game's own cursor cannot be seen there. | 1024x768 only |
| E2 | Any window size, and a real fullscreen at the monitor's resolution, drawn at native resolution. Alt+Enter and the options screen switch between them. On the options screen, a video mode picked in a window sizes the window. Picked in fullscreen, it switches the display to that mode, as the original did, and is remembered (`fullscreenWidth`/`fullscreenHeight`) for Alt+Enter and the next launch. The desktop's own size is always in the list and switches back. E23 covers which mode is the default, and the refresh rate. | 1024x768 or one of the listed video modes |
| E3 | Modern gamepads, mapped by meaning, for both players | Button numbers of the pad's own winmm driver |
| E4 | A keyboard second player | Player 2 needed a joystick |
| E5 | English alongside Portuguese, including the words baked into the menu art | Portuguese only |
| E6 | Settings are kept: language, window, volumes, controls | Options reset at every launch |
| E7 | Plain bugs fixed. `data.enml` has no level-20 threshold, so a player skipped level 20, and past level 30 the experience code never returned. | — |
| E8 | Smooth motion on displays faster than 60 Hz: the world (sprites, lights, shadows, particles, camera) is drawn between the last two ticks, one tick behind. It is a row on the options screen and `smoothMotion` in `settings.json`. It is off under `--fixed-step` unless `--smooth on` is given. | One tick per 60 Hz vsync |
| E9 | Shadows drawn live and ending at the light's reach | Shadows baked into lightmaps, eight times the caster's height |
| E10 | The options screen also sets keyboard player 2, widescreen or 4:3 levels, Portuguese or English, the music and effects volumes in 10% steps, and smooth motion (E8), all saved | The screen had the video modes, pixel shaders, window/fullscreen and the joystick layout, all forgotten at exit |
| E11 | Standing on two floor tiles at once counts as standing | The last tile decided, so the wizard was airborne for one frame at each seam |
| E12 | One gamepad plays the wizard and drives the menu; a second plays the princess | The first pad was player 2's |
| E13 | A pause. In a level or an arena, Esc or player 1's Back freezes the game under Resume / Main menu, with the music at 40%. The clock freezes too, so best times leave the pause out. The pause also opens when the window loses focus (`pauseOnFocusLoss`, a row on the options screen). There is no pause on the end screens, where Esc and Back still go to the menu. | No pause: Esc in a level went straight to the main menu and the run was lost |
| E14 | In the menus, the arena select, the options and game over, a pad's A also confirms and B also goes back | Only Start confirmed and only Back went back |
| E15 | Five ambient sound markers in levels 2 and 3, which the level designer named `play_sound.ent` instead of `play_sound`, now play once when they come on screen, like the correctly named ones | The script collected only the exact name, so those five never played |
| E16 | On-screen touch controls for phones and tablets: a direction disc, jump, sword, fireball, light, the two combos and pause. They press player 1's own keys, and a tap clicks in the menus. The buttons are Magic Rampage's, laid out by `data/touch_controls.json`. While they are on, the control hints name the buttons, not the keys (`touch` in `data/strings.json`). They are set by `touchControls` in `settings.json`, or by `--touch` on a desktop. | Keyboard and joysticks only; hints name the keys |
| E17 | Two open-licence stand-in fonts, drawn at the metrics of the Windows faces they replace (Liberation Sans Bold for Arial and Arial Narrow, DejaVu Sans Bold for Arial Black and Verdana). They are used off Windows, and on a Windows machine that lacks a face. | The Windows system fonts only |
| E18 | MP3 music decoded without Media Foundation (dr_mp3). This is used on every platform but Windows, and on Windows only if Media Foundation refuses a file. | Audiere, on Windows |
| E19 | The first language follows the system off Windows too: Portuguese where `LC_ALL`, `LC_MESSAGES` or `LANG` starts with `pt`, and the device's language on Android and iOS | Portuguese only |
| E20 | The options screen on a phone. It has no video-mode list, no window switch and no "Press Alt+Enter" line; the touch controls' on/off switch takes the window switch's place. | The same screen on every machine |
| E21 | The Credits panel also credits the enhanced edition, after the original team: "Ivan Cvetanović", Enhanced edition (Supersonic Engine). The c with acute cannot be written in the original's Windows-1252 text, so it is drawn from byte 0x8D, which that code page leaves unused. | The 2010 team only |
| E22 | While the touch controls are on, they are player 1 and the first gamepad plays player 2. This makes Versus and the co-op princess playable on a phone with one Bluetooth pad. Without a pad, Versus says to connect one. | A lone pad was player 2's (E12 made it player 1's) |
| E23 | The display mode is chosen for the player, and can be chosen by hand. Automatic fullscreen runs at the desktop's resolution (the monitor's native one, as the system runs it) and at the highest refresh rate the monitor offers there. An automatic window has the monitor's shape and fills 85% of the screen above the taskbar, centred. A first launch is fullscreen. On the options screen, the resolution list starts with "Automatic (best)", shows each size as "WxH", marks the monitor's native size "(native)" and the current choice "[•]". A size picked in a window is centred. The "Refresh rate" row beside the Windowed/Fullscreen switch offers "Automatic (165 Hz)" (the monitor's highest) and every rate the monitor has at the fullscreen resolution. A pick applies at once in fullscreen, or at the next fullscreen from a window. On Android the row asks the display for its highest rate, or for 60 Hz to save the battery. iOS has no row, and iOS itself is untested. The choices are saved as `width`/`height`, `fullscreenWidth`/`fullscreenHeight` and `fullscreenRefresh` (`0` is automatic). | Fullscreen at the mode picked, at whatever rate the driver chose; the list's lines "WxHx32", a size once per refresh rate; no refresh rate to choose |
| E24 | Eleven languages, those of the author's Magic Rampage Companion app: English, German, Spanish, French, Italian, Portuguese, Russian, Turkish, Ukrainian, Japanese and Arabic. The options screen's language row is a chooser that names each language in its own script, whatever the current one. A first launch is in the system's language when the game speaks it (Windows' UI language, the POSIX locale, or the device's language on Android, macOS and iOS), and in English otherwise; the choice is saved as `language` in `settings.json`, and `--lang` takes any of the eleven ids for one run. The text of each language is `data/strings/<id>.json`; anything a file lacks is drawn in English. Japanese and Arabic are drawn from bundled Noto faces on every platform. Arabic letters are joined and read right to left, with Latin names, key names and numbers left to right inside a line, and each paragraph's lines are aligned to its right; the menu's side panel and the pause menu end their text at their right edge, as far in as it starts from the left in the other languages. The words in the menu art are in the language where a picture in it exists (`data/images/<id>/`), and in English otherwise. | Portuguese only (the English edition, E5, added English) |
