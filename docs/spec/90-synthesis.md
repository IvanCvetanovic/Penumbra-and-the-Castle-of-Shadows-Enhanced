- ai-world: the claim that 'Supersonic AudioClip reads only uncompressed RIFF/WAVE (ARCHITECTURE.md:132; README.md:79)' is WRONG. ARCHITECTURE.md:132 is stale. - flow-ui working model (callback phase): the claim that static callbacks run 'after the loop' in the same frame is WRONG. Verified in eth-0.7.12/src/ETHEngine.cpp:565-623 and ETHScene.cpp:421-425, 916-918, 972-1019. One frame runs: SetupProc -> input update -> loop function -> pending LoadScene (plus its preLoop) -> CalcLastFrame -> BeginSpriteScene -> background image -> RenderScene (collects static entities with callbacks whose bucket was drawn) -> DrawTopLayer -> EndSpriteScene/Present -> RunCallbacksFromList (the dynamic-or-temporary list first, every frame whatever their visibility; then the static list collected in this render) -> AngelScript GC step. So both kinds run after Present. Read as a cycle, 'dynamic before the next loop' holds. Consequences: (a) input is refreshed between the callbacks and the next loop. (b) Every callback draw lands in the NEXT frame's top layer, queued ahead of that frame's loop draws. The story text (a static callback) should therefore fade under fadeIn like the HUD does, which contradicts flow-ui's 'story text does not'. Caveat: D3DX text z-behaviour is unverified. (c) When a callback requests LoadScene, the OLD scene's loop runs once more before the load executes. That is why isMainCharDead decrements g_lives exactly once per death.

## Gaps

- Global clock design (not stated as a port requirement by any mapper): GetTime must be ONE app-lifetime monotonic millisecond counter that survives LoadScene. Absolute times are kept in custom data and written into checkpoint.esc: lastLightning, deathTime, lastSwordAttack, lastMpIncr, falling, fadeOut, lastTimeAlive, vanishTime, lastSummon, lastTimeDidntSee, menuStartTime. g_levelStartTime and g_timer are script globals that also survive loads. Every difference is uint32 wraparound arithmetic. Port: one uint32 ms counter advanced by the fixed 60 Hz tick with a fractional accumulator, never reset per scene. Engine-capabilities' 'turn GetTime into SimulationClock ticks' must keep this property.
- Side effects of checkpoint restore that the port must reproduce or deliberately fix. LoadScene resets the camera to (0,0), and doLoop tests spawn markers with isInScreen BEFORE adjustCameraPos, so on the first frame after any load, untriggered markers within the rect (0,0)-(1024,768) +/-76 px spawn whatever the player's position. Saved temporaries, a summoned princess and dying enemies reappear. The checkpoint entity is in its own save, so respawning re-triggers it (it saves again, shows 'Checkpoint...' again and spawns another effect). fase.mp3 is silent. setupScene.as:167 rebuilds g_frameTimers.deleteAll under the preserved IDs. The clouds entity reuses its saved ambientR/G/B.
- Script behaviours missing from the digests. next_level requires player 0 within 80 px AND Down held (getPlayerXYAxis(0).y > 0, main.as:194-224). Only player 0 can take checkpoints or exit a level (the como_jogar text says so too). A summon is refused when the princess is already visible (GetVisibleEntities) or when the box to the right of player 0 collides with something (controlCharacters.as:676-733). The event01 loop has no break, so both players in the bucket give a double king and a double chefao restart. ETHCallback_potion binds to no entity. PlaceInput and GetLastCharInput (eth_util.as:82-94) are unused. The king sets g_gameFinished every frame while it dies (controlCharacters.as:670-673).
- Pixel snapping: cameraManager.as:139 calls SetPositionRoundUp(true) and floors the camera (cameraManager.as:143-146), so entities are rendered at rounded positions with 1:1 texels at 1024x768. The port needs pixel-snapped sprite positions and a 1:1 ortho camera, and must decide the texture filter (the engine always builds mips and filters linearly unless a .meta asks for nearest; those sidecars would have to live in the port's asset copy, not in read-only extracted/app).
- Resolution dependence of gameplay. GetScreenSize() drives: the spawn trigger (isInScreen +/-76); the camera dead zone; which static callbacks run (buckets drawn: help, story, checkpoint, next_level, play, event01, shooter.ent x18, potion_small x54); the princess' off-screen death; falling-bridge deletion; the HUD and menu layout (showData text is 20 vs 25 at height <= 700). The options screen (videoModes.as:85-140) lists 32-bit modes of at least 800x600 and calls SetWindowProperties at runtime. Recommendation: fix a 1024x768 logical resolution and scale it for display, so the logic never changes. This needs Ivan's ruling.
- Persistence. The options g_enablePS, g_windowed and g_controls (videoModes.as:43-45) are script globals that are never written, so they reset on every launch. The original writes only hs.enml (scores.as:88, via enml writeToFile) and scenes/checkpoint.esc (main.as:184), both into its install folder. The port must write to Supersonic::UserDataDirectory(title), seed hs.enml with the defaults (hs0..hs4 = 3599000) and never write into extracted/app. Whether to persist options is a recorded deviation for Ivan to decide. Run machine.exe for parity only on a copy ((a scratch copy of extracted/app) already is one).
- Asset and font licensing, which no mapper raised. The credits (menu.as:152-176) name third-party music, 'Approaching Thunderstorm' (www.freesoundtrackmusic.com), and textures by James Hastings-Trew (planetpixelemporium.com). Arial Narrow, Arial Black, Arial and Verdana are Microsoft fonts that must not be redistributed, so load them from C:\Windows\Fonts at runtime with a free fallback (e.g. Liberation Sans Narrow Bold) when missing. This joins the open repo-policy question (extracted/ and penumbra_setup.exe are already committed and pushed).
- AngelScript failure semantics the C++ port must copy. A null-handle access aborts only the current callback. Example: doDamage.as:176 runs isAMainCharacter(attacker) when SeekEntity(ownerID) returned null because the owner, such as an impy, is dead or deleted. The port should return early at that exact point: the hp reduction and damage number already happened, while that target's knockback and hit effect, and every later target in the call, are skipped. enml.h:663-709 (0.7.12) getInt/getUint/getFloat do not write *p when a key is missing. What value the 2010 AngelScript &out temporary copies back (the lv20 and lv31+ cases in addToExp) is still open.
- Open: particle SFX volume at spawn. m_v2Move is never initialised in the ETHParticleManager constructor (ETHParticleManager.cpp:473-483, member at ETHParticleManager.h:263). gsGetDist2 lives in closed GameSpaceLib 1.6.4.1, not in gs2d-r485. If GS_VECTOR2 default-constructs to (0,0), the first HandleSoundPlayback subtracts dist(origin, entity)/screenDiagonal and clamps to 0.2, so every spawned sword or hit sound would start at 20% and climb +0.01 per frame. Verify with a listening test on a copy of machine.exe or by disassembly before copying it.
- Top-layer and background details. DrawTopLayer (ETHEngine.cpp:634-671) draws with camera (0,0), z-buffer and z-write ON and sprite depth 0. DrawRectangle's depth defaults to 0 too, so equal depth under LESSEQUAL means call order. Primitives with time=0 are one-shot. The background image is drawn BEFORE the scene with camera (0,0) and m_bgAlpha (ETHEngine.cpp:591-604). ScreenOverlay draws after the scene, so the background layer (dawn/fog images, the additive planets.png at (0.6*W,100) size 329x329) must be a camera-attached world quad behind everything, not an overlay. The environment entities are moved to camera + (64,350) every frame (environment.as:124-126), so their particle emitters are camera-attached.
- frameTimer (ETHFrameTimer.cpp in 0.7.12, Set(first,last,stride)/Get()) drives every character animation. player-combat reports 'strict >' from 2013 knowledge; re-derive it from eth-0.7.12/src/ETHFrameTimer.cpp:62. Scripts write frames directly (SetFrame), so the engine's SpriteAnimationComponent should NOT be used for characters. Use uvScale/uvOffset per frame instead.
- The 0.7.12 source lives in the session Temp scratchpad, which can be cleaned. Copy eth-0.7.12 (LGPL; it includes TinyXML under zlib and enml.h) and gs2d-r485 into a gitignored reference/ folder in the Penumbra repo, as MPR does with reference/ethanon. Cite them there from now on instead of the 2013 clone. Cross-game coordination: the vertical slice needs zero engine changes. ## Module breakdown

LAYOUT (mirrors MPR): the Penumbra repo root CMakeLists.txt has a submodule guard, then add_subdirectory(engine) (pinned at 4bfcf67, never the live Desktop checkout), game/ and tests/. game/sim is a static library holding all game/sim/*.cpp at /W4. A separate PenumbraLayer library lets tests attach the layer to a bare registry. Data paths are CACHE PATH compile definitions: PENUMBRA_ORIGINAL_DIR = extracted/app (read-only), PENUMBRA_PORT_DATA_DIR = the port's converted/keyed assets and .meta sidecars, PENUMBRA_REFERENCE_DIR = reference/ (gitignored, holding eth-0.7.12 and gs2d-r485). Saves go through Supersonic::UserDataDirectory. Tests are tests/test_pn_*.cpp via supersonic_add_test, wrapped as add_pn_test(name [SKIPS_WITH_77]).

MODULES (game/sim):
A. Foundation
 - Cp1252: text is kept as cp1252 bytes, with a UTF-8 conversion only for logs.
 - Enml: parse/write. A missing key leaves the out-param unwritten. \; and \\ escapes, CRLF kept in values. writeToFile must reproduce the hs.enml layout.
 - EthXml: a minimal legacy-encoding XML reader/writer.
 - EthFormats: EntityDef (type, static, collidable, startFrame, applyLight, castShadow, blendMode, layerDepth, soundVolume, shadow*, specular*, Emissive, SpriteCut, PivotAdjust, Sprite/Normal/Gloss, up to 2 ParticleSystemDefs with SoundEffect, LightDef, CollisionDef, CustomData), SceneFile (SceneProperties with ambient, lightIntensity, ZAxisDirection) and instances (id, spriteFrame, EntityName, Color, Position). The inline block wins for scene placements; AddEntity loads entities/*.ent.
 - Assets: stb_image plus content sniffing (the BMP named .jpg), colour key, DDS decode, normal-map renormalise, UploadRGBA; path resolution across the original and port-data roots.
 - Clock: one app-lifetime uint32 ms GetTime advanced by the 60 Hz tick; UnitsPerSecond(x) = x/60; GetFPSRate = 60.
B. Runtime (the 'Ethanon machine')
 - World: entity store with ids, the next id = max+1 rule and soft delete; CustomData; buckets; GetEntitiesFromBucket, GetEntityArray, SeekEntity, GetVisibleEntities, CollideDynamic; the callback registry by label (strip the extension).
 - Scheduler: the exact 0.7.12 phase order. Input, then loop, then pending LoadScene and preLoop, then render, then the top layer, then callbacks (dynamic/temporary first, then the statics drawn this frame), then temporary cleanup.
 - SceneIO: LoadScene (release all, camera (0,0), bake lightmaps) and SaveScene snapshot/restore to UserDataDirectory.
 - Input: key 4-state machine; two GLFW joysticks with JK buttons and +/-0.8 arrows; a virtual cursor; the g_controls mapping.
 - SampleBank: basename-keyed samples, OGG via stb_vorbis plus AddClip, restart/loop/volume/pan, release on load.
 - ParticleSim: the 0.7.12 ETHParticleManager simulation, repeat counting, temporary-entity auto-delete, SoundEffect start and HandleSoundPlayback. This part is gameplay-critical.
C. Presentation
 - SpriteView: entity to engine Quad. Frame UVs from SetFrame/spriteFrame, origin per ENTITY_TYPE plus pivot, pixel snap, colour/alpha, blendMode 0 -> Alpha, blendMode 2 -> cutout, drawHash -> sortKey, ortho 1024x768 with a +Y flip, flyControlsEnabled=false.
 - Lighting: ambient/emissive; dynamic Light2D only from visible owners; halos; LightmapBaker. Shadows come later, and specular/vertical once the engine supports them.
 - ParticleDraw: pooled quads, the additive/modulate emulation, depth interleaving.
 - TopLayer: DrawText/DrawSprite/DrawShapedSprite/DrawRectangle queued in call order, one-shot, with callback draws carried into the next frame. It sits over ScreenOverlay.
 - Fonts: imstb_truetype atlases, bold faces, GDI cell height.
 - Background: colour, image, additive.
D. Gameplay (one module per .as family)
 - Physics (util.as move/applyForce/knockBack/boxes plus doCharacterCollision)
 - Characters (frameTimer, animateCharacter, isDead/isMainCharDead, spawn())
 - Player (playerInput.as, combo.as, player1Summoner)
 - Weapons (swords.as, spells.as, doDamage.as)
 - EnemyAI (characterAI.as melee/ranged/mixed, summoner, enemy callbacks)
 - Hazards (instant_death*, lavaShooter.as, falling_bridge)
 - Pickups (potions.as)
 - Camera (cameraManager.as, earthquake, round-up)
 - Messages (messageManager.as, damage numbers)
 - Hud (interface.as)
 - Triggers (setupScene.as setup/doLoop spawn and play_sound; help, story, checkpoint, next_level, play, event01)
 - Environment (clouds lightning, fog, dawn)
 - Progress (lives, exp/levels, timer.as, scores.as)
 - Menu (menu.as, arena_select thumbnails and locks)
 - Options (videoModes.as, switch.as)
 - GameOver (gameover.as)
 - Pvp (pvpLoop, points, win screen)
 - PenumbraLayer plus main.cpp (the MPR pattern: GameManifest, ValidationErrorCount check, absolute --screenshot paths).
